# ERAF + FG：从 all5_off200 继续的 CF 优先实验

2026-09-07 用户更新目标：优先让 ERAF+FG 超过其他版本；可扩数据、修改监督、微调结构，所有变更留痕；尽量保住现有 CF，不对 Correct 设要求，自行开关服务器。

本轮优先验证已有五任务数据能否通过真正联合优化和更强 CF 保持改善 ERAF+FG。十任务评测范围保留，额外五任务此轮仍为迁移测试；尚未宣称完成它们的数据扩充或学会其 CF。结构本轮保持不变。

## 证据与改动

目前 all5_off200 在原五任务新开发集 CF19/30，Correct25/30，十任务宏平均CF31.7%。之前 Full200+ERAF 是 Full200 策略与单独10步接口的推理组合，没有共同优化；它的原五任务新开发CF16/30。因此应先完成从最强共同策略出发的接口预热和联合训练。

- 三组从同一 all5_off200 策略开始：普通CF、FG、ERAF+FG。明确标注 warm-policy 初始化，不改写父checkpoint的训练历史。
- CF教师由 Shared400换为 all5_off200。保留原始数据、原始路径和所有旧权重。
- batch12从 Correct4/CF2/专家3/FG3改为 Correct2/CF4/专家3/FG3；Correct权重1、CF权重4、FG或普通CF替换权重1。此配方应用到全部新组。
- 策略只更新Action LoRA，lr3e-6。ERAF+FG先冻结策略训练接口100步、lr1e-4，再共同训练400策略步，接口lr3e-5。分别报告额外接口步骤，不能宣称总FLOPs相同。
- 关闭三组同义指令增强，避免此前FG与Off增强比例不同。普通CF与FG的批内任务/域和非纠正位置仍匹配。
- 按任务、域、场景、帧采样；任务权重不因域数量不同而翻倍。
- ERAF语义训练另增加全部声明任务及source/target各自的通过条件，避免好任务或原指令掩盖新任务CF关系错误。本轮不重新训练语义头。

## 评测与可归因范围

每组保存200、400两个策略检查点。以固定五任务、每任务六CF场景做开发筛选，完整结果优先、同分选较早步；同一矩阵重评 all5_off200。每组都选取自己的最好checkpoint，避免只优化ERAF的选择机会。

再对选中ERAF+FG的同一权重关闭ERAF复评，检查模块是否实际贡献；选中三个训练组和共同父模型再评另外五任务，每任务三个CF场景。原任务、语言、物理初始状态和动作预算均使用原来的固定协议。独立test保持未打开；开发结果不得描述成独立测试结论或统计显著优势。

主结论需要十任务宏平均及逐任务CF、相同场景回退/新成功列表。若ERAF+FG没超过对照，继续报告失败并据证据调整数据或监督，不改成功判据。Correct不是本轮筛选门槛，CF筛选阶段只跑CF；如后续报告Correct，单独注明实际评测范围。

## 执行与留痕

`scripts/run_robotwin_cf_priority_campaign.py` 默认只写protocol；加 `--execute` 才启动训练。各训练组各用两卡；全部训练完成后六卡评测。每次运行必须使用新输出目录及带时区的绝对截止时间。

```bash
cd /root/gpufree-data/LF-FastWAM-eraf-fg
/opt/conda/bin/python -u scripts/run_robotwin_cf_priority_campaign.py \
  --output /root/gpufree-data/LF-FastWAM/runs/robotwin_cf_priority/UNIQUE_RUN \
  --deadline 'YYYY-MM-DDTHH:MM:SS+08:00' --execute
```

实际日期和输出目录由每轮启动记录固定。启动前设置平台定时关机，工作截止前预留备份时间；无任务需要GPU时提前关机。用户允许自主开关不代表需要持续占卡。

每轮保存protocol（代码提交、父权重、教师、样本配方、学习率、开关、预算）、各组plan、逐步样本/损失日志、优化器状态、所有候选权重、逐回合评测、视频和完整/失败driver记录。仅记录文件路径/大小/mtime并验证实际权重绑定，不反复扫描大型文件hash。

本次新增的程序测试覆盖：CF失败不能被语义总均值掩盖；任务采样平衡；FG对照位置匹配；不同学习率仍准确恢复优化器；共同父权重不能泄漏FG训练到Off对照；不完整或Correct指标不能用于CF筛选。CPU测试不证明真实GPU训练或闭环改善，后者须由实际运行验证。
