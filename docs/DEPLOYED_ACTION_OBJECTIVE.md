# Direct deployed-action supervision

Motivation: completed initial-anchor CF did not improve ERAF+FG (23.33% ten-task macro against strongest35%). A subsequent20-state/model semantic-oracle intervention did not repair fixed-state action fit. This motivates testing the action objective; it does not prove that the old objective caused the failure.

`--action-objective deployed_rollout_v1` explicitly replaces the flow/endpoint objective. The default remains `flow_endpoint_v1`. The new objective starts from noise with no expert action input, builds the same current visual/language/proprio context, and differentiates through all ten production Euler denoising steps. Activation checkpointing changes storage, not the gradient horizon. Only the first24 executed action positions with real valid labels receive MSE. Same-observation source/target pairs retain the conditional-difference gain; nonidentical states cannot use this term. Full-goal corrective rows still cover the complete corrective episode in the bank, while matched FG-off slots retain ordinary target-only data.

Retention samples match the corresponding teacher's ten-step sampled actions from the same starting noise. Teacher adapter swaps complete and restore before any student graph is built. CF teacher remains the strongest preserved model; Correct is reported but is not an outcome constraint. No oracle semantics, expert-conditioned noisy states, post-sampler action edits, or additional inference steps are introduced.

The objective name is recorded in the immutable optimizer contract, checkpoints, per-example journals and stage audits. Resuming an optimizer across objectives is forbidden. The first feasibility run changes zero weights: two existing semantic1500 parents with the same strongest action policy,20 selected expert states each, exact production-versus-new-sampler equality with ERAF on/off, then backward-only checks for the four actual first-batch strata with ERAF on/off. It checks actual parameter identity, finite gradients, memory and time. All model payloads stay on the server. The controller has a15-minute process-only cutoff.

Next training is conditional on this actual feasibility evidence. Its steps, learning rates, four-arm pairing, output storage budget and CF evaluation must be declared before launch. Feasibility is not a performance result, and the performance goal remains unchanged.
